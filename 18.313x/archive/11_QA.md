# Skeptic's Review — Exchange 11

## Question

In the component 4 of `complete_information_extraction` would it help to include reference comment Rota's entropy properties of `isEntropyZeroInvariance` and `isEntropyZeroOnEmptyDomain`?

*[Context: The user had implemented the conditional entropy / information extraction argument in PPNP.lean, with `complete_information_extraction` bundling 5 components. Component 4 proved Bool decidability of `evalCNF`. The question was whether referencing two specific Rota axioms would strengthen the "zero remaining entropy" claim.]*

## Answer

Yes, referencing both would strengthen the conceptual argument in component 4, and here's exactly why each one matters for it.

**`IsEntropyZeroOnEmptyDomain`** (`H(∅) = 0`) is the more directly relevant of the two. After the walk has visited every clause (which component 1 proves via `walk_visits_every_clause`), the domain of unprocessed clauses is empty. This axiom formalizes the claim that the remaining information to be extracted is exactly zero — there are no clauses left to process, so no conditional entropy remains. It's the formal justification for "the walk exhausts the information content of the CNF."

**`IsEntropyZeroInvariance`** (`H(p₁,...,pₙ,0) = H(p₁,...,pₙ)`) plays a subtler but important supporting role. It says that hypothetically extending the domain with zero-probability outcomes doesn't create new information. In the SAT context, this addresses the question: "what about assignments you didn't check?" After the walk extracts all clause-level information, the answer for any specific assignment is determined — any "additional" outcome you might conceptually append contributes zero probability mass and therefore zero entropy. This axiom says that entropy is robust to such phantom extensions.

Together they close the entropy argument from both sides: ZeroOnEmptyDomain says "nothing left to process → zero entropy," and ZeroInvariance says "adding vacuous alternatives doesn't change that."

That said, there's a meaningful distinction between adding these as a reference comment versus formalizing the connection. Right now, component 4 proves `evalCNF cnf v = true ∨ evalCNF cnf v = false`, which is Bool decidability — trivially true. The deeper claim you're making is that after the walk, no *additional computation beyond reading* is needed to determine satisfiability. A reference comment citing these two axioms would make the reasoning chain explicit for a reader, which is valuable. But the stronger move would be to eventually formalize a lemma like:

```lean
/-- After the walk visits every clause, the conditional entropy of the
    satisfiability decision given the walk record is zero.
    Uses IsEntropyZeroOnEmptyDomain (no unvisited clauses remain)
    and IsEntropyZeroInvariance (vacuous extensions preserve this). -/
theorem walk_exhausts_cnf_entropy {k : ℕ} (cnf : SyntacticCNF_EGPT k)
    (endpoint : { v : Vector Bool k // evalCNF cnf v = true }) :
    -- remaining conditional entropy after walk = 0
    ...
```

That would turn the comment into a theorem and formally close the gap at component 4. For now though, adding the reference comment is the right intermediate step — it documents exactly which proven axioms support the claim and tells a reader (or a future formalization pass) precisely where to look.
