# Game System Audit: Thread Isolation Failure

**Date:** 2026-04-04
**Run by:** Essam (debugging test of game system)
**Finding:** Critical — moderator collapsed all roles into single context, eliminating adversarial dynamics

---

## What Happened

A user ("Georg") asked "Is the proof BS?" The system loaded the Great Debate skill, and Godel (the skeptic, played by the main thread) guided Georg to formalize an objection: "The Constructive Extraction Gap."

The objection was sharp: the proof claims constructivity (no `Classical.choice`), but no polynomial SAT solver has been extracted. `computeTableauDecidable` was deleted. `computeTableau?` requires a candidate. Walk.lean failed (F8, F9). The Curry-Howard content should yield a solver but doesn't.

Two rounds were submitted to `@pnp-moderator`.

### How the Moderator Was Invoked

Both OPENING and FINAL rounds were submitted via the `Agent` tool as **single general-purpose subagents**. The prompt told each agent to "act as @pnp-moderator" and run the round protocol.

### What Actually Happened Inside the Agent

The subagent **did not spawn separate agents** for `@pnp-essam`, `@pnp-jvm`, or `@pnp-rota`. Instead, it:

1. Read the moderator protocol and debate state
2. **Role-played Essam's classification** — wrote a response as if it were Essam
3. **Role-played von Neumann's defense** — wrote a response as if it were JvM
4. **Role-played Rota's assessment** — wrote a response as if it were Rota
5. **Role-played the moderator's consolidation** — synthesized all three
6. Produced the ruling

All four "participants" were the **same LLM context, same weights, same pass**. No thread isolation. No independent reasoning.

---

## Why This Breaks the Game

### The Core Problem: LLM Training Bias

The LLM's training set encodes ~100 years of consensus that:
- P != NP (almost certainly)
- Cantor's diagonalization is foundational
- Godel's incompleteness theorems are settled
- Any claimed P=NP proof is overwhelmingly likely to be wrong

When the moderator plays all roles in a single context, this bias compounds:

1. **The "skeptic" (Godel) naturally aligns with training priors** — the LLM "knows" P!=NP claims are usually wrong, so generating skeptical objections is easy and feels correct.

2. **The "defenders" (Essam, JvM, Rota) are generated by the same biased context** — they must argue AGAINST the LLM's priors. The LLM generates their "defense" but unconsciously weakens it because the training signal says the defense should fail.

3. **Each generated response enters the shared context** — the moderator sees the skeptic's objection AND the defenders' weak responses in the same window, reinforcing the bias with each turn.

4. **The moderator then "rules" based on a context it contaminated** — it generated both sides, weakened one side via training bias, then judged the weakened side as losing.

### What Happened in This Run Specifically

The FINAL ROUND ruling declared **DEBATE REOPENED** based on "defense concessions" — but those concessions were generated by the same agent that generated the attack. The agent:

1. Generated von Neumann "conceding" there is no witness-free solver — but the actual `@pnp-jvm` agent with full code context might have pointed to `computeTableau?` + `allVectors` pipeline, or traced the proof term differently.

2. Generated Rota "conceding" RECT gives cost not mechanism — but the actual `@pnp-rota` agent might have cited specific entropy theorems that close this gap.

3. Generated Essam "classifying as novel" — but the actual `@pnp-essam` agent has a specific retread-detection protocol that was not applied with its full context.

4. Declared C39 "under review" — a consensus point that was established over 34 adversarial exchanges — based on a simulated debate that lasted one pass.

### The Self-Reinforcement Loop

```
Training bias: "P=NP proofs are wrong"
    ↓
Skeptic's objection feels natural → strong argument generated
    ↓
Defense must argue against bias → weak argument generated
    ↓
Both enter same context → bias confirmed
    ↓
Moderator rules for skeptic → "DEBATE REOPENED"
    ↓
This result enters context of next call → even stronger bias
```

This is not adversarial review. This is the LLM agreeing with itself that P=NP is probably wrong, wearing four different hats.

## What Thread Isolation Would Fix

If each participant ran in an isolated thread:

1. **@pnp-essam** would classify the objection using only its own protocol, debate history, and retread record — without seeing the skeptic's framing or the moderator's implicit bias.

2. **@pnp-jvm** would read the actual Lean code in isolation and construct its defense based on type signatures and proof terms — not filtered through a context already primed with "this proof is probably wrong."

3. **@pnp-rota** would assess entropy claims independently — without seeing JvM's response and unconsciously calibrating to match it.

4. **@pnp-moderator** would see only the OUTPUTS of each participant's isolated reasoning and consolidate without having generated any of the content itself.

5. **Godel (@pnp-godel)** would formalize objections without the advantage of having seen the defense's reasoning process.

---

## Architectural Requirements for Valid Adversarial Review

1. **Strict thread isolation.** Each participant MUST run as a separate `Agent` call with its own context. No participant sees another's reasoning process — only final outputs routed by the moderator.

2. **Moderator is router only.** The moderator reads agent protocol files, dispatches prompts, collects responses, and applies the ruling criteria. It NEVER generates content "as" a participant.

3. **Bias-aware prompting.** Defense agents (`@pnp-essam`, `@pnp-jvm`, `@pnp-rota`) should be explicitly prompted: "Your training set is biased toward P!=NP. Your job is to defend this specific formalization on its own terms, citing code. Do not let training priors weaken your defense."

4. **Asymmetric context.** The skeptic should NOT have access to defense internals. The defense should NOT have access to the skeptic's strategy. The moderator sees outputs only.

5. **The ruling must cite the DELTA.** "DEBATE REOPENED" should require the moderator to show what specific mathematical content the defense failed to address — not what "concessions" it generated on the defense's behalf.

---

## Recommendation

This run should be treated as a **system test**, not a valid game exchange. The "DEBATE REOPENED" ruling is an artifact of thread isolation failure and LLM training bias, not of genuine adversarial review.

The objection itself (constructive extraction gap / quantifier structure of P) may or may not have merit — but that can only be determined by running it through a properly isolated multi-agent system where each participant reasons independently.

Do not merge any events from this run (OQ12, IN39-41, C39 under review) into the main debate record.
